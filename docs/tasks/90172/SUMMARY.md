## Что было

При правке времени дня в Заявке валидный день 09:00–21:00 (рабочий день проекта 09:00–21:00) получал «Время позже изначального» (баг №3 Прогона #1, TC-2006): форма читала рабочие часы проекта как местное время, хотя сервер хранит их в UTC — в API приходило 06:00–18:00. В просмотре время «21:00» дополнительно превращалось в «021:00» проверкой ведущего нуля.

## Что сделано

- `bid.tsx` (режимы правки и просмотра): рамка проекта собирается с суффиксом Z — по эталону `activity.tsx`; проверка `startsWith("0")` с дописыванием нуля убрана.
- `bid.service.ts` (`getDefaultTimeRange`, запасная рамка из глобальных настроек): тот же принцип эталона — Z, без дописывания нуля.
- `job.tsx` (форма Работы Специалиста): правка не вносилась — сдвиг невоспроизводим, форма `JobMobileFormView` закомментирована в маршруте (job.tsx:284-306), валидация времени не исполняется (Д-3).
- Верификация UTC-фикса (временные e2e, notes/, gitignored): день 09:00–21:00 MSK при часах проекта 06:00/18:00 UTC — ложных ошибок нет; 08:00 → «раньше», 22:00 → «позже»; A/B на старом коде воспроизводит баг. Полный прогон Playwright (40 тестов): падения — те же 10, что на чистом main в этом окружении, новых нет. Typecheck: 157 ошибок (бейзлайн), в правимых файлах чисто.
