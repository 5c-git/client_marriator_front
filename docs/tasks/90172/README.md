## Постановка

**ЦЕЛЬ ЗАДАЧИ:**
Убрать ложную ошибку «Время позже/раньше изначального» при правке времени дней в Заявке (баг №3 Прогона #1, TC-2006) и исключить тот же сдвиг в форме Работы Специалиста. Родительская задача: #88945.

**КАК РАБОТАЕТ СЕЙЧАС:**
При правке времени дня в Заявке (проект с рабочим днём 09:00–21:00) день 09:00–21:00 получает ошибку «Время позже изначального» (после выбора точки маршрута, когда запускается полная проверка формы). Ошибка «раньше» при выходе за границу проекта при этом не срабатывает как ожидается.

**ПРИЧИНА (установлена 28.10.2026):**
Сервер хранит рабочие часы проекта в UTC: админка при сохранении вычитает 3 часа, при показе добавляет (ProjectController.php:45-46, 65-66). API отдаёт сохранённое значение: у проекта 12 в ответе getBid timeStart «06:00», timeEnd «18:00», при том что в админке 09:00–21:00.
Форма Заявки читает это время как местное: app/routes/bids/bid/bid.tsx строки 118, 121 (режим правки) и 157, 160 (просмотр) собирают Date без суффикса Z. В консоли defaultTimeRange = 03:00Z–15:00Z, то есть 06:00–18:00 по Москве вместо 09:00–21:00. Конец дня 21:00 оказывается «позже 18:00».
Для сравнения: в услуге Задачи (app/routes/activity/activity.tsx:105-108) то же время собирается с Z, и ошибки нет. Сама проверка в обеих формах одинакова (ActivityFormMobileView.tsx и BidFormMobileView.tsx), менять её не нужно.
Серверная часть правки не требует: сервер последовательно считает рабочие часы проекта в UTC.

**ЧТО НУЖНО СДЕЛАТЬ:**
1. bid.tsx:118, 121, 157, 160: собирать рамку проекта с суффиксом Z, как в activity.tsx:105-108. Заодно убрать проверку startsWith("0") с добавлением нуля в просмотре (строки 157, 160): время вроде «21:00» превращается в «021:00» (невалидная дата).
2. app/routes/bids/bid/bid.service.ts:46-58 (getDefaultTimeRange, запасной вариант из глобальных настроек intervalDayStart/End): собирается без Z, а в activity.tsx тот же запасной вариант с Z. Определить, в каком поясе хранятся глобальные настройки, и привести к одному правилу. Если неясно — вернуть вопрос Владимиру Кормишину.
3. app/routes/jobs/job/job.tsx:52-55 (форма Работы Специалиста): рамки строятся без Z, а в JobMobileFormView.tsx те же тексты и та же проверка. По коду сдвиг вероятен, на практике не воспроизводился. Проверить воспроизведением и при подтверждении исправить так же.

**КРИТЕРИИ ПРИЕМКИ:**
1. Проект с рабочим днём 09:00–21:00: день 09:00–21:00 в форме Заявки (после выбора точки маршрута и при сохранении) ошибки не даёт; в консоли defaultTimeRange 09:00–21:00 по местному времени.
2. Время 08:00 (раньше начала) и 22:00 (позже конца) в форме Заявки дают ошибку.
3. Те же проверки для формы Работы Специалиста.
4. Услуга в Задаче работает как раньше.
5. Повторный прогон TC-2006 (qadesk run 361) проходит этот шаг.

**ЗАМЕЧАНИЕ О ТЕКСТАХ ОШИБОК:**
Текст «Время раньше/позже изначального» используется и для границ проекта, и для границ самой Заявки (начало только вперёд, конец только назад). Предложение заменить на два разных текста ждёт согласования постановщика и в эту подзадачу не входит.
