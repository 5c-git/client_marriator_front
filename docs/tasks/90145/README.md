## Постановка

*(текст с портала, 27.10.2026)*

**ЦЕЛЬ ЗАДАЧИ:**
Убрать возможность править услугу Поручения после его отправки (баг №1.2 Прогона #1, TC-2001, видео 3:15). Родительская задача: #88945.

**КАК РАБОТАЕТ СЕЙЧАС:**
После «Отправить поручение» (статус «Не принято», код 2) пользователь возвращается на страницу new-order/:orderId («назад» в браузере или прямой адрес), и у услуги остаётся карандаш: услугу можно редактировать. Удалить услугу нельзя (проверено Владимиром Кормишиным 28.10.2026 на preprod).
По ТЗ после отправки редактирование Поручения невозможно (docs/10-lifecycle/04-order/04_send.md:33). Сервер правку в статусе «Не принято» разрешает, запрет держится только интерфейсом; решение постановщика 27.10.2026: ограничение делаем только на фронте.

**ПРИЧИНА В КОДЕ ФРОНТА:**
Загрузчик страницы app/routes/orders/new-order/new-order.tsx (clientLoader) получает заказ, но статус не проверяет. На странице заказа (order.tsx:335) и в activity.tsx (setting_canEdit) правка уже доступна только при статусе 1, там проблемы нет.

**ЧТО НУЖНО СДЕЛАТЬ:**

1. В clientLoader страницы new-order/:orderId: если статус заказа не 1 («Новый»), перенаправлять на /orders/:orderId (или не показывать карандаш).
2. Проверить, что у неотправленного Поручения (статус 1) всё работает как раньше.

**КРИТЕРИИ ПРИЕМКИ:**

1. Отправить Поручение, вернуться «назад» или открыть new-order/:orderId вручную: формы редактирования и карандаша у услуги нет.
2. У Поручения в статусе «Новый» создание и правка услуг работают как раньше.
3. Повторный прогон TC-2001 (qadesk run 361) не позволяет править услугу после отправки.

**ПРИМЕЧАНИЕ:**
Защиты на бэкенде нет, запрет можно обойти прямым запросом API. Это принятое ограничение.
