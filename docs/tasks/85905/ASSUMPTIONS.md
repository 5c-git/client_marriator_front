# Журнал допущений — задача #85905

Строка появляется каждый раз, когда исполнитель принимает решение, **не следующее из постановки**. Это не пересказ хода рассуждений, а перечень развилок, на которых постановка молчала.

Журнал ведётся **по ходу работы**, а не восстанавливается в конце: восстановленный по памяти журнал содержит то, что запомнилось, а не то, где был риск.

Читатели: постановщик (на сверке) и сверка `task-test` шага 2. Агенту слепого тест-дизайна этот файл **не показывается** — он и есть канал заражения, от которого защищает изоляция слепого дизайна (`task-test`, Шаг 1).

---

## Д-1. Сообщение при истечении интервала

- **Что неоднозначно:** решение «интервал истёк к моменту «Да» → на сервер ничего не отправляется» не говорит, что видит пользователь.
- **Что выбрал:** модалка закрывается, Snackbar «Время для отмены … истекло»; кнопка исчезает при перерисовке.
- **Почему:** молчаливое закрытие модалки выглядит как сбой; тот же Snackbar, что и для ошибки API.
- **Что сломается, если выбор неверен:** лишнее сообщение — косметика.
- **Риск:** обычный
- **Затронуто:** `app/routes/bids/bid/bid.tsx`, `app/routes/tasks/task/task.tsx`, `app/routes/orders/order/order.tsx` — обработчик «Да»

## Д-2. Что считать ошибкой отмены

- **Что неоднозначно:** «ошибка API» не определена; в обсуждении 02.07 был случай «200, а статус старый».
- **Что выбрал:** ошибка = исключение из `postCancel*` (сеть, не-JSON, ответ не по схеме) **или** `data.success === false`. 401 не перехватывается — остаётся штатный перелогин через `ErrorBoundary`.
- **Почему:** схема ответа `{ data: { success: boolean } }` — `success: false` единственный сигнал отказа при 200.
- **Что сломается, если выбор неверен:** если бэк при успехе отдаёт `success: false` — пользователь увидит ошибку при фактической отмене.
- **Риск:** обычный
- **Затронуто:** `clientAction` в трёх файлах выше

## Д-3. Тексты новых сообщений

- **Что неоднозначно:** формулировки ошибки и истечения интервала в постановке и ТЗ отсутствуют.
- **Что выбрал:** RU — «Не удалось отменить заявку/задачу/поручение. Попробуйте ещё раз», «Время для отмены заявки/задачи/поручения истекло»; EN — термины как в соседних ключах (`request` / `task` / `order`).
- **Почему:** нейтральные формулировки в стиле существующих текстов.
- **Что сломается, если выбор неверен:** правка текста в `public/locales/{ru,en}/m_{bids_bid,tasks_task,orders_order}.json`.
- **Риск:** обычный
- **Затронуто:** 6 файлов локалей

## Д-4. Заголовок модалки — как на мобилке

- **Что неоднозначно:** постановка — «Отменить заявку?», мобильные модалки рендерят «Отменить заявку ?» (пробел перед «?»), и QA их приняла.
- **Что выбрал:** те же ключи и та же сборка строки, что в мобильных списках.
- **Почему:** единообразие десктоп/мобилка; пробел — общий для приложения, править глобально и отдельно.
- **Что сломается, если выбор неверен:** QA может завести косметический баг на пробел.
- **Риск:** обычный
- **Затронуто:** `DialogTitle` в трёх файлах
