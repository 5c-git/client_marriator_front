### Дефекты

#### V-1 [LOW] EN: «assignment» vs «order» в текстах ошибки отмены поручения

- **Файлы:** `public/locales/en/m_orders_order.json` (новые ключи), `public/locales/en/m_orders.json`
- **Что:** в EN-цепочке поручения кнопка и модалка говорят «Cancel order» (`m_orders`), а новые сообщения об ошибке/истечении — «Failed to cancel **the assignment**…», «The time to cancel **the assignment** has expired» (`m_orders_order`). В RU всё едино («поручение»), расхождение только в EN.
- **Сценарий:** англоязычная локаль → отмена поручения с упавшим API → пользователь читает «Cancel order?» в модалке и «Failed to cancel the assignment» в снекбаре — воспринимается как два разных объекта.
- **Фикс (на выбор):** в `en/m_orders_order.json` заменить «assignment» → «order» в `cancelErrorAlert`/`cancelExpiredAlert`, либо (если терминология проекта — «assignment») наоборот выровнять `m_orders` и кнопку.
- **Статус:** исправлено в 2bb5bc3

#### V-2 [LOW] Окно повторного клика: `fetcher.reset()` в `onClose` снекбара сбрасывает state при идущем повторном запросе

- **Файлы:** `bid.tsx:237-243`, `task.tsx:828-834`, `order.tsx:801-807`
- **Что:** `Snackbar.onClose` (автозакрытие через 3с, Esc, клик вне) безусловно зовёт `fetcher.reset()` / `cancelFetcher.reset()`. Если первая отмена упала (снекбар открыт) и пользователь успел нажать «Да» повторно до автозакрытия, таймер сработает **во время** второго запроса: reset переведёт `state` в `idle`, кнопка отмены на короткое время снова активна (формальное нарушение критерия 5), возможен третий параллельный запрос.
- **Сценарий:** отмена → ошибка API → снекбар открыт → в течение 3с снова «Да» → ответ второго запроса ещё не пришёл → автозакрытие снекбара → `reset()` → кнопка активна при запросе в полёте.
- **Последствие:** косметика + потенциальный дубль запроса отмены (на сервере скорее всего просто `success:false`). Блокирующим не считаю.
- **Фикс:** не сбрасывать fetcher по таймеру — чистить только источник показа, например гейтить reset: `onClose={(_, reason) => { setCancelExpired(false); if (reason !== "timeout") cancelFetcher.reset(); }}` — либо показывать снекбар из локального state, синхронизированного эффектом с `fetcher.data`.
- **Статус:** исправлено в 2bb5bc3

### Ответ (Claude Code, 2026-09-30)

Дефект подтверждаю. Предложенный гейт по `reason !== "timeout"` закрывает таймер, но не Esc/клик вне при запросе в полёте — сделал иначе, во всех трёх файлах:

- `open` = `(fetcher.state === "idle" && fetcher.data?.cancelError) || cancelExpired` — пока идёт повторный запрос, снекбар скрыт, MUI снимает его таймер; ответ с ошибкой снова открывает снекбар со свежим таймером, успешный (`data` → `undefined`) — не открывает;
- `onClose` зовёт `reset()` только при `state === "idle"`.

Итог: `reset()` посреди запроса невозможен ни по одному `reason`, кнопка остаётся неактивной до ответа. typecheck — в изменённых файлах 0 ошибок, eslint — 0 ошибок, build ✅.
