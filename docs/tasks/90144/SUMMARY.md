# Задача #90144 — 422 на getTask после сохранения услуги в новой Задаче

- **Период:** 2026-10-28 — 2026-10-28
- **Статус:** ✅ закрыта

## Что было

После сохранения услуги в только что созданной Задаче (без ухода со страницы) пользователь видел страницу ошибки 422: редирект вёл на `/tasks/new-task?taskId=950`, такой адрес совпадает с маршрутом `:lang?/tasks/:taskId`, где `:taskId` = слово «new-task», и loader вызывал `getTask("new-task")`. Для Поручений то же с «new-order» — ошибка «The order id field must be an integer» из Прогона #1 (баг №1.1, TC-2001, родительская #88945).

## Что сделано

- В `clientAction` формы услуги (`app/routes/activity/activity.tsx`) isNew-редирект после сохранения ведёт на `/<plural>/<new>/<entityId>` (формат работавшей ветки createService) — исправлена ветка updateService, источник 422.
- Один action на Задачи и Поручения (словарь `vocabulary`): правка закрыла обе ошибки, включая ошибку Поручения на `/orders/1015`.
- Fallback по ответу постановщика №1: если entityId — не целое положительное число, редирект на список сущности (`/tasks` / `/orders`); применён к обеим веткам сохранения.
- Двойной сабмит не предотвращается (решение постановщика: выполняет те же действия, что и одиночный); чужие id — права разбирает сервер.
