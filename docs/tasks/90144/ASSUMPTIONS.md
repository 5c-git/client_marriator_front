# Журнал допущений — задача #90144

Строка появляется каждый раз, когда исполнитель принимает решение, **не следующее из постановки**. Это не пересказ хода рассуждений, а перечень развилок, на которых постановка молчала.

Журнал ведётся **по ходу работы**, а не восстанавливается в конце: восстановленный по памяти журнал содержит то, что запомнилось, а не то, где был риск.

Читатели: постановщик (на сверке) и сверка `task-test` шага 2. Агенту слепого тест-дизайна этот файл **не показывается** — он и есть канал заражения, от которого защищает изоляция слепого дизайна (`task-test`, Шаг 1).

---

## Д-1. Fallback на список — в обеих ветках сохранения

- **Что неоднозначно:** ответ постановщика №1 говорил про «после сохранения» без различения веток createService/updateService; постановка («что нужно сделать» п.1) требовала правку только в updateService.
- **Что выбрал:** проверка «entityId — реальное число» и fallback на список применены к обеим isNew-веткам (единый `newEntityPath`).
- **Почему:** createService с битым id вёл бы на `/tasks/new-task/NaN` — тот же класс ошибки; условие в одном месте, а не в двух.
- **Что сломается, если выбор неверен:** в гипотетическом сценарии «createService с невалидным id» пользователь увидел бы страницу ошибки вместо списка; здесь — уйдёт на список.
- **Риск:** обычный
- **Затронуто:** `app/routes/activity/activity.tsx:150-165` (clientAction)

---

## Д-2. Форма адресов: isNew-редирект без withLocale, fallback — с withLocale

- **Что неоднозначно:** в action смешаны стили: isNew-ветка createService — без `withLocale`, else-ветки — с ним.
- **Что выбрал:** основной isNew-адрес — без `withLocale` (зеркало работающей createService, названной постановкой верной); fallback на список — `withLocale(`/${plural}`)` (как else-ветки).
- **Почему:** маршруты `:lang?` принимают оба вида; выбран вид ближайшего работающего соседа в каждой ветке.
- **Что сломается, если выбор неверен:** при не-русской локали пользователь теоретически мог бы потерять префикс языка; поведение не хуже эталонной createService.
- **Риск:** обычный
- **Затронуто:** `app/routes/activity/activity.tsx:150-165`

---

## Д-3. else-ветки (сохранение без isNew) не тронуты

- **Что неоднозначно:** ответ №1 не различал режимы сохранения.
- **Что выбрал:** fallback добавлен только в isNew-ветки; else-ветки (`/${plural}/${entityId}`) оставлены как есть.
- **Почему:** в else-режиме entityId приходит со страницы уже открытой сущности (реальный id по построению); объём задачи — баг №1.1 только в isNew-сценарии.
- **Что сломается, если выбор неверен:** окажись путь до else-ветки с битым id — страница ошибки останется; сценарий не известен.
- **Риск:** обычный
- **Затронуто:** `app/routes/activity/activity.tsx:163` (не изменена)
