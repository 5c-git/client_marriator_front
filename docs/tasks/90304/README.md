## Постановка

**ЦЕЛЬ ЗАДАЧИ:**
Кнопка «Отменить» у Поручения и Задачи видна тогда и только тогда, когда сервер принимает отмену. Бэкенд с задачей #89553 отдаёт в API флаг canCancel — фронт перестаёт считать окна сам и переходит на флаг. Черновик без услуг получает кнопку «Отменить».

**ЧТО НУЖНО СДЕЛАТЬ:** (репозиторий client_marriator_front, ветка от main)

1. Типы ответов API: добавить canCancel: boolean в типы карточки и списка Поручения и Задачи (getOrder/getOrders/getTask/getTasks).
2. Списки (orders.tsx, tasks.tsx) и карточки (order.tsx, task.tsx): видимость кнопки «Отменить» — по canCancel из ответа вместо ButtonActionMapper.canCancelNewOrNotAccepted / canCancelAccepted. Раскладка кнопок (десктоп — детальная карточка, мобилка — список, модалка подтверждения) не меняется — решение 18.09.2026 по #85905.
3. Повторная проверка в модалке («окно истекло, пока модалка была открыта»): перезапрос карточки перед отправкой или осознанное упрощение — решение зафиксировать в документации.
4. getUserIntervals (orders.service.ts, tasks.service.ts): интервалы cancel_order / cancel_task для кнопки отмены больше не используются (остаются для «Повторить»); убрать зависимость разделов «Поручения» и «Задачи» от наличия этих настроек (TD-119 для отмены уходит).
5. buttonActionMapper: ветки отмены убрать, canRepeatCancelled не трогать.
6. Заявки (bid.tsx) не трогать — окно отмены Заявки вне объёма (TD-118).

**КЛЮЧЕВЫЕ СЛУЧАИ:**

- черновик без услуг (Поручение и Задача): кнопка есть, отмена в любой момент — сейчас локальная формула без дат кнопку прячет (критерий 1 задачи #89553);
- принятое Поручение/Задача: кнопка живёт до «дата окончания + срок действия», то есть дольше даты окончания — сейчас пропадает на date_end;
- сочетание «кнопка есть, сервер 422» не возникает ни в одном случае.

## Вопросы к постановщику

Шаг 5.5, 2026-10-30 — 5 вопросов. Сверка с документацией (бэкенд-канон 06/04_cancel_and_repeat.md) и кодом фронта тем же днём закрыла все пять — постановщику остаются на утверждение вместе с критериями.

1. **Конфликт п. 5 и п. 6 (маппер vs Заявки) — снят.** Заявки buttonActionMapper не используют: отмена Заявки живёт своей логикой внутри bid.tsx (cancelAction/cancelDialogOpen, без маппера). Ветви отмены из маппера убираются, canRepeatCancelled остаётся. Источник: потребители маппера — только orders.tsx, order.tsx, tasks.tsx, task.tsx (grep по app/).
2. **Повторная проверка из списка (мобилка) — снят.** Решение п. 3 действует в модалке независимо от точки входа — модалка одна и та же. Сегодня в модалке списка повторной проверки нет вообще (orders.tsx:330-344, tasks.tsx аналогично; в бэкенд-доке повторная проверка оговорена только «на десктопе»), то есть протухший флаг списка сегодня может дать 422. Переход на canCancel с перезапросом в модалке закрывает и этот случай: инвариант «кнопка есть — 422 не возникает» держится на перезапросе, а не на свежести списка.
3. **Отсутствие поля canCancel — снят.** Критерий 1 (видна ⇔ canCancel = true) допускает единственное прочтение: undefined ≠ true → кнопка скрыта. Это безопасная деградация («кнопки нет» вместо «кнопка + 422»). Примечание к релизу: в origin/main бэкенда коммитов #89553 нет (ветка feature/task-89553-… локальна) — фронт должен уезжать после бэка, иначе на время разрыва у принятых кнопка пропадёт.
4. **Выбор варианта по п. 3 — решён: перезапрос карточки перед отправкой.** «Осознанное упрощение» (отправить и поймать 422) противоречит ключевому случаю 3 постановки («кнопка есть — сервер 422 не возникает ни в одном случае»); перезапрос сохраняет текущий UX десктопа — «Время для отмены истекло», запрос не уходит (канон, разделы «Кнопка и подтверждение»). Точечные методы есть: getOrder (order.tsx:73), getTask (task.tsx:70).
5. **Частичный отказ запроса интервалов — снят.** Обязанность «не ломать разделы» (п. 4, критерий 5) касается отсутствия значений настроек при успешном ответе: cancel_order для отмены больше не нужен, отсутствие change_order лишь прячет «Повторить» (NaN-интервал → сравнение false, buttonActionMapper.ts:14). Полный отказ запроса getUserInfo/getUserIntervals остаётся падением лоадера с текущей страницей ошибки — как сегодня у любого падения лоадера, в объём задачи не входит.
