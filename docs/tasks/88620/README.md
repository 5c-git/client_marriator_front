## Решения по вопросам Шага 5.5 (ответы постановщика, 2026-10-15)

1. Хранение — **localStorage** браузера.
2. Статус **выживает** при F5 и при закрытии/повторном открытии приложения.
3. Срок жизни — **бессрочно** (рекомендация исполнителя принята: без TTL и без очистки; малый объём данных, см. п. 4).
4. Состояние **не наследуется** другим аккаунтом → ключ хранения включает идентификатор пользователя.
5. Ключ статуса — **название**; если названия нет в списке статусов — правила постановки: сброс на первый по очереди от сервера.
6. Порядок статусов от сервера **стабилен**.
7. Трансформация поручения → задача: открывать **сохранённый статус раздела задач** (фильтруем по статусам самого раздела).
8. «Назад» браузера и прямые ссылки восстанавливают статус **так же**, как возврат из карточки.
9. Несколько вкладок: актуально **последнее сохранённое** значение (last write wins).
10. Пункты 3 и 5 постановки — **об одном и том же** в разных ситуациях; поведение единое: нет статуса в списке → первый от сервера.
11. Частичный отказ сервера — **не зона задачи**: ошибка перехватывается выше в приложении.
12. Отзыв прав — **не зона задачи**: сервер вернёт ошибку, приложение покажет её.
13. Разделы: **четыре** — поручения, задачи, заявки, модерация клиентов.
14. Сохраняется **только статус** (без пагинации, прокрутки, поиска и прочих фильтров).
15. Пустой статус: достаточно **пустого списка**, специальное нулевое состояние не нужно.

Ограничение реализации от постановщика: **не менять контракты API сервера** (набор данных запросов/ответов остаётся как есть); следовать правилам `react-rules` из KB (рекомендации тимлида FrontEnd).
